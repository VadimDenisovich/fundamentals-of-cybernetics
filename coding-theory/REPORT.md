## 1. Введение

### 1.1 Цель работы

Провести сравнительный анализ помехоустойчивости кодов Рида–Соломона (РС) и БЧХ (BCH), используя готовые библиотеки кодирования/декодирования, с фокусом на:

- **(А)** сравнение двух независимых реализаций одного и того же кода;
- **(Б)** сравнение режимов работы кодов (разные коды с одинаковой исправляющей способностью, разные модели каналов).

### 1.2 Краткий обзор кодов РС и BCH

**Коды БЧХ (Боуза–Чоудхури–Хоквингема)** — класс циклических кодов, исправляющих кратные ошибки. Двоичный BCH-код длины n = 2^m − 1, исправляющий t ошибок, задаётся порождающим многочленом g(x) = НОК(M₁(x), M₃(x), …, M₂ₜ₋₁(x)), где Mᵢ(x) — минимальный многочлен элемента αⁱ поля GF(2^m). Корнями g(x) являются α, α², …, α^2t (narrow-sense код), что гарантирует конструктивное расстояние d ≥ 2t+1.

**Коды Рида–Соломона** — частный случай недвоичных BCH-кодов, у которых алфавит символов совпадает с полем локаторов: символы кодового слова — элементы GF(q), длина n = q − 1. Порождающий многочлен: g(x) = (x − α)(x − α²)⋯(x − α^2t), степень n − k = 2t. РС-коды — МДР-коды (достигают границы Синглтона d = n − k + 1) и исправляют любые t = (n−k)/2 символьных ошибок. Так как ошибка в символе «стоит» одинаково независимо от числа испорченных бит внутри символа, РС-коды особенно эффективны против пакетных ошибок.

**Декодирование обоих классов** выполняется по одной схеме:
1. вычисление синдромов Sᵢ = r(αⁱ), i = 1…2t;
2. нахождение многочлена локаторов ошибок Λ(x) — **алгоритм Берлекэмпа–Месси (БМ)**;
3. поиск корней Λ(x) перебором — **процедура Чиеня**; позиции ошибок j: Λ(α^−j) = 0;
4. для недвоичных кодов — значения ошибок по **формуле Форни**: eⱼ = −Ω(Xⱼ⁻¹)/Λ′(Xⱼ⁻¹), где Ω(x) = S(x)Λ(x) mod x^2t (для двоичных кодов значение ошибки всегда 1 — бит просто инвертируется).

Ниже оба алгоритма продемонстрированы письменно на примерах в GF(2³). Все вычисления продублированы и подтверждены скриптом `tools/verify_manual_examples.py`; кодовые слова из примеров используются как валидационные векторы (`src/codingtheory/validation.py`).

#### Поле GF(2³)

Поле строится по примитивному многочлену p(x) = x³ + x + 1, α — примитивный элемент, корень p(x): **α³ = α + 1**. Элементы поля (запись битами b₂b₁b₀ ↔ b₂α² + b₁α + b₀):

| Степень | Многочлен | Биты | Целое |
|---|---|---|---|
| 0 | 0 | 000 | 0 |
| α⁰ | 1 | 001 | 1 |
| α¹ | α | 010 | 2 |
| α² | α² | 100 | 4 |
| α³ | α + 1 | 011 | 3 |
| α⁴ | α² + α | 110 | 6 |
| α⁵ | α² + α + 1 | 111 | 7 |
| α⁶ | α² + 1 | 101 | 5 |

Сложение — поразрядный XOR битовых записей; умножение — сложение степеней по модулю 7 (α⁷ = 1). В поле характеристики 2 вычитание совпадает со сложением.

#### Пример 1. Код РС(7,3), t = 2 над GF(2³): кодирование и декодирование

**Параметры.** n = 7, k = 3, n − k = 4 = 2t, исправляет t = 2 символьные ошибки, d = n − k + 1 = 5.

**Порождающий многочлен.** g(x) = (x + α)(x + α²)(x + α³)(x + α⁴). Раскрываем попарно:

- (x + α)(x + α²) = x² + (α + α²)x + α³ = x² + α⁴x + α³, так как α + α² = 010 ⊕ 100 = 110 = α⁴;
- (x + α³)(x + α⁴) = x² + (α³ + α⁴)x + α⁷ = x² + α⁶x + 1, так как α³ + α⁴ = 011 ⊕ 110 = 101 = α⁶, α⁷ = 1.

Перемножаем результаты:

(x² + α⁴x + α³)(x² + α⁶x + 1) = x⁴ + (α⁶ + α⁴)x³ + (1 + α¹⁰ + α³)x² + (α⁴ + α⁹)x + α³

- коэффициент при x³: α⁶ + α⁴ = 101 ⊕ 110 = 011 = α³;
- при x²: 1 + α¹⁰ + α³ = 1 + α³ + α³ = 1 (α¹⁰ = α³);
- при x: α⁴ + α⁹ = α⁴ + α² = 110 ⊕ 100 = 010 = α (α⁹ = α²).

**g(x) = x⁴ + α³x³ + x² + αx + α³**

**Кодирование (систематическое).** Сообщение **m = (α, 1, α³)**, т.е. m(x) = αx² + x + α³. Кодовое слово: c(x) = m(x)·x⁴ + r(x), где r(x) = m(x)·x⁴ mod g(x).

Делим m(x)·x⁴ = αx⁶ + x⁵ + α³x⁴ на g(x) «столбиком»:

*Шаг 1.* Старший член αx⁶: частное αx². Вычитаем αx²·g(x) = αx⁶ + α⁴x⁵ + αx⁴ + α²x³ + α⁴x²:

- x⁵: 1 + α⁴ = 001 ⊕ 110 = 111 = α⁵; x⁴: α³ + α = 011 ⊕ 010 = 001 = 1;
- остаток: α⁵x⁵ + x⁴ + α²x³ + α⁴x².

*Шаг 2.* Частное α⁵x. Вычитаем α⁵x·g(x) = α⁵x⁵ + α⁸x⁴ + α⁵x³ + α⁶x² + α⁸x = α⁵x⁵ + αx⁴ + α⁵x³ + α⁶x² + αx:

- x⁴: 1 + α = α³; x³: α² + α⁵ = 100 ⊕ 111 = 011 = α³; x²: α⁴ + α⁶ = 110 ⊕ 101 = 011 = α³;
- остаток: α³x⁴ + α³x³ + α³x² + αx.

*Шаг 3.* Частное α³. Вычитаем α³·g(x) = α³x⁴ + α⁶x³ + α³x² + α⁴x + α⁶:

- x³: α³ + α⁶ = 011 ⊕ 101 = 110 = α⁴; x²: α³ + α³ = 0; x: α + α⁴ = 010 ⊕ 110 = 100 = α²;
- остаток: **r(x) = α⁴x³ + α²x + α⁶**.

Кодовое слово: c(x) = αx⁶ + x⁵ + α³x⁴ + α⁴x³ + 0·x² + α²x + α⁶, в векторной записи (от старшей степени к младшей):

**c = (α, 1, α³, α⁴, 0, α², α⁶) = (2, 1, 3, 6, 0, 4, 5)**

Проверка: c(α) = c(α²) = c(α³) = c(α⁴) = 0 — слово принадлежит коду (подтверждено скриптом; кодер `galois.ReedSolomon(7,3)` даёт то же слово — валидационный вектор №1).

**Канал: вносим две ошибки.** e(x) = α²x⁵ + αx² (позиции x⁵ и x², значения α² и α). Принято:

**r = c + e = (α, α⁶, α³, α⁴, α, α², α⁶) = (2, 5, 3, 6, 2, 4, 5)**

(в позиции x⁵: 1 + α² = 001 ⊕ 100 = 101 = α⁶; в позиции x²: 0 + α = α).

**Декодирование. Шаг 1: синдромы** Sᵢ = r(αⁱ), i = 1…4. Покажем S₁ полностью:

S₁ = r(α) = α·α⁶ + α⁶·α⁵ + α³·α⁴ + α⁴·α³ + α·α² + α²·α + α⁶
= α⁷ + α¹¹ + α⁷ + α⁷ + α³ + α³ + α⁶ = 1 + α⁴ + 1 + 1 + α⁶ = 1 + α⁴ + α⁶ = 001 ⊕ 110 ⊕ 101 = 010 = **α**

(использовано α⁷ = 1, α¹¹ = α⁴; слагаемые 1+1 и α³+α³ взаимно уничтожаются). Аналогично (так как c(αⁱ) = 0, синдромы равны e(αⁱ)):

- S₂ = e(α²) = α²·α¹⁰ + α·α⁴ = α¹² + α⁵ = α⁵ + α⁵ = **0**
- S₃ = e(α³) = α²·α¹⁵ + α·α⁶ = α¹⁷ + α⁷ = α³ + 1 = 011 ⊕ 001 = 010 = **α**
- S₄ = e(α⁴) = α²·α²⁰ + α·α⁸ = α²² + α² = α + α² = 010 ⊕ 100 = 110 = **α⁴**

Синдромы ненулевые — ошибки есть. S = (α, 0, α, α⁴).

**Шаг 2: алгоритм Берлекэмпа–Месси.** Начальные значения: Λ(x) = 1, B(x) = 1, L = 0. На итерации k вычисляется дискрепанс d = Sₖ + Σᵢ₌₁^L λᵢSₖ₋ᵢ; при d ≠ 0 выполняется коррекция Λ(x) ← Λ(x) + d·x·B(x) (с обновлением L и B(x), если 2L ≤ k−1; иначе B(x) ← x·B(x)).

| k | Sₖ | дискрепанс d | Λ(x) после шага | L | B(x) после шага |
|---|---|---|---|---|---|
| 1 | α | d = S₁ = α | 1 + αx | 1 | α⁶ |
| 2 | 0 | d = S₂ + λ₁S₁ = 0 + α·α = α² | 1 + αx + α²·α⁶x = 1 (αx + αx = 0) | 1 | α⁶x |
| 3 | α | d = S₃ + λ₁S₂ = α + 0 = α | 1 + α·x·α⁶x = 1 + x² | 2 | α⁶ |
| 4 | α⁴ | d = S₄ + λ₁S₃ + λ₂S₂ = α⁴ + 0 + 0 = α⁴ | 1 + x² + α⁴·x·α⁶ = 1 + α³x + x² | 2 | α⁶x |

Пояснения: на k=2 коррекция α²·x·(α⁶) = α⁸x = αx гасит слагаемое αx; длина L не растёт (2L = 2 > k−1 = 1), поэтому B ← xB. На k=3 дискрепанс ненулевой и 2L = 2 ≤ k−1 = 2: L ← k − L = 2, B ← Λ_старое/d = 1/α = α⁶. На k=4 (2L = 4 > 3) — только коррекция Λ; α⁴·α⁶ = α¹⁰ = α³.

**Λ(x) = 1 + α³x + x², deg Λ = L = 2 — две ошибки.**

**Шаг 3: процедура Чиеня** — перебор позиций j = 0…6, проверка Λ(α^−j) = 0:

| j | α^−j | Λ(α^−j) |
|---|---|---|
| 0 | 1 | 1 + α³ + 1 = α³ |
| 1 | α⁶ | α |
| **2** | α⁵ | 1 + α³·α⁵ + α¹⁰ = 1 + α + α³ = 001⊕010⊕011 = **0** ✓ |
| 3 | α⁴ | α |
| 4 | α³ | 1 |
| **5** | α² | 1 + α³·α² + α⁴ = 1 + α⁵ + α⁴ = 001⊕111⊕110 = **0** ✓ |
| 6 | α | α³ |

Корни: x = α⁵ и x = α², т.е. локаторы ошибок X₁ = α², X₂ = α⁵ — ошибки в позициях **x² и x⁵** (совпадает с внесёнными). Проверка факторизации: Λ(x) = (1 + α²x)(1 + α⁵x) = 1 + (α² + α⁵)x + α⁷x² = 1 + α³x + x² ✓.

**Шаг 4: формула Форни.** Многочлен значений ошибок:

Ω(x) = S(x)·Λ(x) mod x⁴, где S(x) = S₁ + S₂x + S₃x² + S₄x³ = α + αx² + α⁴x³.

(α + αx² + α⁴x³)(1 + α³x + x²) = α + α⁴x + (α + α)x² + (α⁴ + α⁴)x³ + … ≡ **α + α⁴x** (mod x⁴)

Формальная производная: Λ′(x) = α³ (от α³x; производная x² в характеристике 2 равна нулю). Значения ошибок eⱼ = Ω(Xⱼ⁻¹)/Λ′(Xⱼ⁻¹):

- позиция 2: X⁻¹ = α⁻² = α⁵; Ω(α⁵) = α + α⁴·α⁵ = α + α² = α⁴; e₂ = α⁴/α³ = **α** ✓
- позиция 5: X⁻¹ = α⁻⁵ = α²; Ω(α²) = α + α⁴·α² = α + α⁶ = 010 ⊕ 101 = 111 = α⁵; e₅ = α⁵/α³ = **α²** ✓

**Шаг 5: исправление.** ĉ = r + e: из позиции x⁵ вычитаем α² (α⁶ ⊕ α² = 101 ⊕ 100 = 001 = 1), из x² вычитаем α (α ⊕ α = 0):

ĉ = (α, 1, α³, α⁴, 0, α², α⁶) = c — **переданное слово восстановлено, сообщение m = (α, 1, α³)**.

#### Пример 2. Код BCH(7,4), t = 1 над GF(2): кодирование и декодирование

**Параметры.** Двоичный narrow-sense BCH длины n = 2³ − 1 = 7 с t = 1 (эквивалент кода Хэмминга). Порождающий многочлен — минимальный многочлен элемента α поля GF(2³): **g(x) = x³ + x + 1**, n − k = 3, k = 4. Корни g(x): α, α², α⁴ — в том числе α и α² подряд, значит d ≥ 3.

**Кодирование.** Сообщение **m = (1, 0, 0, 1)**, m(x) = x³ + 1. Делим m(x)·x³ = x⁶ + x³ на g(x):

- *Шаг 1:* частное x³; x³·g(x) = x⁶ + x⁴ + x³; остаток: x⁴;
- *Шаг 2:* частное x; x·g(x) = x⁴ + x² + x; остаток: **r(x) = x² + x**.

Кодовое слово: c(x) = x⁶ + x³ + x² + x, **c = (1, 0, 0, 1, 1, 1, 0)**.

Проверка: c(α) = α⁶ + α³ + α² + α = 101 ⊕ 011 ⊕ 100 ⊕ 010 = 000 = 0 ✓ (кодер `galois.BCH(7,4)` даёт то же слово — валидационный вектор №2).

**Канал: одна ошибка** в позиции x⁴: r(x) = c(x) + x⁴, **r = (1, 0, 1, 1, 1, 1, 0)**.

**Декодирование. Синдромы** (для t = 1 нужны S₁, S₂):

S₁ = r(α) = α⁶ + α⁴ + α³ + α² + α = 101 ⊕ 110 ⊕ 011 ⊕ 100 ⊕ 010 = 110 = **α⁴**

S₂ = r(α²) = S₁² = α⁸ = **α** (в поле характеристики 2 верно r(x²) = r(x)², поэтому S₂ вычисляется возведением в квадрат).

**Алгоритм Берлекэмпа–Месси:**

| k | Sₖ | дискрепанс d | Λ(x) после шага | L | B(x) после шага |
|---|---|---|---|---|---|
| 1 | α⁴ | d = S₁ = α⁴ | 1 + α⁴x | 1 | α³ (= 1/α⁴) |
| 2 | α | d = S₂ + λ₁S₁ = α + α⁴·α⁴ = α + α⁸ = α + α = 0 | 1 + α⁴x (без изменений) | 1 | α³x |

**Λ(x) = 1 + α⁴x, L = 1 — одна ошибка.**

**Поиск корня (Чиень).** Λ(α^−j) = 0 ⇔ 1 + α⁴·α^−j = 0 ⇔ α^j = α⁴ ⇔ **j = 4**. (Проверка: Λ(α⁻⁴) = 1 + α⁴·α³ = 1 + α⁷ = 1 + 1 = 0 ✓.)

**Исправление.** Код двоичный — инвертируем бит в позиции x⁴:

ĉ = (1, 0, 0, 1, 1, 1, 0) = c — **слово восстановлено, сообщение m = (1, 0, 0, 1)**.

### 1.3 Два направления сравнения

- **Направление А — сравнение реализаций одного кода.** Код RS(255, 223, 16) над GF(2⁸) реализуется библиотеками `galois` и `reedsolo`; обе реализации прогоняются в идентичных условиях (одна модель канала BSC, одинаковые N_blocks, p_range, seed — побайтово совпадающие сообщения и реализации шума). Измеряются FER, BER и время декодирования на блок.
- **Направление Б — сравнение режимов работы кодов.** На одной библиотеке (`galois`, чтобы исключить фактор реализации) сравниваются коды RS(15,11,2) над GF(2⁴) и двоичный BCH(15,7,2) — оба длины 15 с t = 2 — в двух моделях каналов: BSC (независимые битовые ошибки) и Burst (пакетные ошибки длиной до 8 бит).

### 2.2 Модели каналов

Все каналы реализованы самостоятельно (`src/codingtheory/channels.py`), работают с кадрами битов и принимают внешний генератор случайных чисел (фиксированный seed → воспроизводимость).

**BSC (двоичный симметричный канал).** Каждый бит независимо инвертируется с вероятностью p:

yᵢ = xᵢ ⊕ eᵢ, eᵢ ~ Bernoulli(p), i.i.d.

Параметры: p ∈ p_range.

**SymbolError (канал символьных ошибок).** Кадр делится на m-битные символы; каждый символ независимо с вероятностью p_s заменяется на случайный *другой* символ (XOR с равновероятной ненулевой маской из GF(2^m)\{0}):

sᵢ ← sᵢ ⊕ uᵢ, uᵢ ~ U(GF(2^m)\{0}) с вероятностью p_s.

Параметры: p_s, m. Для этого канала существует точная формула FER декодера с ограниченным расстоянием, что используется для валидации Монте-Карло (раздел 2.4).

**Burst (пакетный канал).** С вероятностью p_burst на кадр вносится один пакет ошибок: непрерывный участок случайной длины L ~ U{1,…,L_max} со случайным началом s ~ U{0,…,n_bits − L} (пакет целиком внутри кадра); все биты участка инвертируются:

yᵢ = xᵢ ⊕ 1 при s ≤ i < s + L, иначе yᵢ = xᵢ.

Параметры: p_burst, L_max = 8.

Валидация каналов: эмпирические частоты ошибок при фиксированном seed согласуются с заданными параметрами в пределах 4σ; для Burst дополнительно проверяются непрерывность пакета и ограничение длины (валидационный вектор №5, тесты `tests/test_channels.py`).

| Канал | BSC | BSC и Burst(L ≤ 8 бит) |

| p_range | 8 точек, logspace 0.004…0.015 | BSC: 10 точек 0.003…0.3; Burst: 10 точек 0.001…0.3 |
| seed | 20260 (общий для обеих библиотек) | 20261 (общий для всех конфигураций) |

Коды направления Б имеют одинаковую длину n = 15 и одинаковую исправляющую способность t = 2 ошибки на кодовое слово; избыточность n − k = 4 единицы алфавита (4 символа GF(2⁴) у RS, что составляет 16 бит на 60-битный кадр; 8 бит на 15-битный кадр у BCH). Различие избыточности в битах (26.7% против 53.3%) обсуждается при интерпретации результатов.

N_blocks = 10⁵ для направления Б обеспечивает статистическую значимость при FER ~ 10⁻³ (ожидаемое число ошибочных кадров ~100). Для направления А выбрано N_blocks = 10⁴ (достаточно по критерию гипотезы А2, N ≥ 10⁴): декодер `reedsolo` написан на чистом Python, и 10⁵ блоков на точку сделали бы эксперимент многочасовым без улучшения качества выводов — сравнение реализаций проводится в области «колена» кривой FER, где FER ≥ 10⁻², т.е. ≥100 ошибочных кадров на точку.

Идентичность условий в направлении А обеспечена конструктивно: при одинаковом seed, batch_size и одинаковых (n, k) обе библиотеки получают побайтово одинаковые сообщения и одинаковые реализации шума, а благодаря выравниванию fcr — и одинаковые кодовые слова (проверено валидацией).

### 2.4 Метрики и статистика

**FER (Frame Error Rate)** — доля кадров, декодированных с ошибкой:

FER = N_err_frames / N_blocks, кадр ошибочен, если декодированное сообщение ≠ переданному.

При отказе декодера (обнаружена неисправимая комбинация) во всех обёртках применяется одинаковая стратегия passthrough: берётся информационная часть принятого слова.

**BER (Bit Error Rate)** — доля ошибочных бит в декодированных сообщениях (по информационным битам):

BER = N_err_bits / (N_blocks · k_bits).

**Throughput** — скорость декодирования: Throughput = N_blocks · k_bits / T_decode [бит/с]; также приводится время декодирования на блок T_decode/N_blocks. Время измеряется только для операции декодирования (`time.perf_counter()`), JIT-компиляция galois выполняется до замеров (warm-up).

**Доверительные интервалы (95%).** Для оценки доли p̂ = k/N используется интервал Вальда:

p̂ ± 1.96·√(p̂(1 − p̂)/N).

**Проверка значимости различий.** Двухвыборочный z-тест для долей (pooled):

z = (p̂₁ − p̂₂) / √(p̄(1−p̄)(1/N₁ + 1/N₂)), p̄ = (k₁ + k₂)/(N₁ + N₂),

двусторонний p-value = erfc(|z|/√2); различие считается значимым при p-value < 0.05.

**Валидация Монте-Карло на известных векторах** (`python -m codingtheory.validation`, все 5 проверок входят в pytest):

1. RS(7,3) над GF(2³): кодовое слово (2,1,3,6,0,4,5), вычисленное вручную в разделе 1.2, совпадает с кодером galois;
2. BCH(7,4): кодовое слово (1,0,0,1,1,1,0) из раздела 1.2 совпадает с кодером galois;
3. BCH(15,7): порождающий многочлен galois совпадает с табличным g(x) = x⁸ + x⁷ + x⁶ + x⁴ + 1 (Лин, Костелло, табл. 6.1);
4. RS(255,223): galois и reedsolo (fcr = 1) дают побайтово идентичные кодовые слова;
5. статистическая валидация трёх каналов (частоты ошибок в пределах 4σ, непрерывность пакета).

Дополнительно кривая FER Монте-Карло для RS(15,11,2) в канале SymbolError сопоставлена с точной теоретической кривой FER = P(>t символьных ошибок) = 1 − Σᵢ₌₀² C(15,i)·p_sⁱ·(1−p_s)^(15−i):

![Валидация Монте-Карло](results/validation_symbol_channel.png)

Эмпирическая кривая (точки с 95% CI) на всём диапазоне совпадает с точной теоретической кривой FER декодера с ограниченным расстоянием — цикл Монте-Карло и реализация символьного канала корректны. «Колено» кривой проходит около p_s ≈ t/n = 2/15 ≈ 0.133, что согласуется с теоретическим порогом (раздел 4.4).

### 3.4 Интерпретация

**Почему FER совпадает точно?** При одинаковых seed, batch_size и (n, k) обе библиотеки получают побайтово идентичные сообщения, идентичные кодовые слова (выравнивание fcr подтверждено валидацией) и идентичные реализации шума. Декодер с ограниченным расстоянием детерминирован: кадр исправляется тогда и только тогда, когда в нём ≤ t = 16 символьных ошибок, — а это свойство принятого слова, не реализации. Поэтому множества ошибочных кадров у двух библиотек совпадают поэлементно, и FER/BER равны точно. z-тест лишь формализует этот факт.

**Почему `galois` оказался в ≈52 раза *медленнее*, а не быстрее? Гипотеза А2 опровергнута.** Векторизация numpy в `galois` ускоряет арифметику поля, но декодер RS вызывается **поблочно**: цикл Берлекэмпа–Месси, поиск Чиеня и формула Форни для каждого из 10⁴ кадров выполняются отдельным вызовом с диспетчеризацией numba и созданием типизированных GF-массивов. Для длинного кода n = 255 фиксированные накладные расходы на блок (≈110 мс) доминируют. `reedsolo` — чистый Python, но это компактный однопроходный декодер одного блока без overhead на инфраструктуру массивов; здесь он выигрывает на порядок. Векторизация `galois` дала бы выигрыш при батч-обработке многих коротких слов или при операциях над всем массивом сразу, но не в режиме «один длинный блок за вызов». Вывод: преимущество векторизации не универсально и зависит от гранулярности вызовов.

**Ответы на вопросы направления А:**

1. *Дают ли библиотеки статистически одинаковые FER/BER?* — Да, причём идентичные с точностью до кадра (z = 0, p = 1.0 на всех точках): один код, один алгоритм, одинаковые входные данные.
2. *Насколько отличается время и в чём причина?* — `reedsolo` в ≈52 раза быстрее на RS(255,223) при поблочном декодировании. Причина — накладные расходы `galois` на блок (numba-диспетчеризация, аллокация GF-массивов) при длинном коде; преимущество векторизации не реализуется в режиме «один блок за вызов».
3. *Какая библиотека удобнее?* — `reedsolo`: простой байтовый API (`RSCodec(nsym).encode/decode`), не требует numba, мгновенный импорт. `galois` требовательнее к окружению (numba/llvmlite), первый вызов включает JIT-компиляцию, но даёт строгую типизацию GF-массивов и единообразную работу с полем.
4. *Ограничения каждой библиотеки?* — `reedsolo` ориентирована на байтовые символы GF(2⁸) (универсальные поля поддержаны, но менее удобны) и только RS. `galois` поддерживает произвольные GF(p^m), а также BCH, Хэмминга, реализует РС/BCH/линейные коды в общем виде — что и использовано в направлении Б.

### 4.4 Интерпретация

**Почему при одинаковой избыточности (n − k = 4) коды ведут себя по-разному?** «Одинаковая избыточность» в единицах алфавита различается в битах: BCH(15,7) — 8 проверочных бит на 15-битный кадр (53.3%), RS(15,11) — 4 проверочных символа на 60-битный кадр (16 из 60 бит, 26.7%). Кроме того, единица исправления у кодов разная: RS считает **символьные** (4-битные) ошибки, BCH — **битовые**.

- **В BSC выигрывает BCH.** Независимые битовые ошибки рассеяны: при вероятности p на бит символ GF(2⁴) повреждается с вероятностью ≈ 1 − (1 − p)⁴ ≈ 4p. RS «развёрнут» в 60 бит и при бюджете t = 2 символа имеет вчетверо бо́льшую экспозицию, тогда как BCH защищает короткий 15-битный кадр и тратит вдвое больше проверочных бит. Итог — FER BCH на 1–2 порядка ниже. Это уточняет гипотезу Б3: в BSC коды **не** «сопоставимы» — при равной символьной избыточности, но разной битовой, BCH заметно лучше.
- **В пакетном канале выигрывает RS.** Пакет длиной ≤ 8 бит затрагивает ≤ ⌈8/4⌉ + 1 = 3, а чаще ≤ 2 соседних символа GF(2⁴) — в пределах исправляющей способности RS (t = 2 символа). Для двоичного BCH тот же пакет — до 8 независимых *битовых* ошибок, что вчетверо превышает его бюджет t = 2. Поэтому RS даёт FER в ≈ 3–4 раза ниже. **Гипотеза Б1 подтверждена.**

**Как тип канала влияет на выбор кода?** Принципиально. Кроссовер кривых (BCH ниже в BSC, RS ниже в Burst) — прямая иллюстрация: для независимых ошибок предпочтительны двоичные коды с высокой битовой избыточностью; для пакетных — символьные коды (РС), у которых пакет «стягивается» в малое число символов. На практике именно поэтому РС применяют против пакетных искажений (CD/DVD, QR, DVB), часто в связке с перемежением. **Часть гипотезы Б3 о переходе преимущества к RS в пакетном канале подтверждена.**

**Согласие с теоретическим порогом p ≈ t/n.** «Колено» кривых FER ожидается там, где среднее число ошибок на кадр достигает исправляющей способности:

- BCH в BSC: порог по битам p ≈ t/n = 2/15 ≈ 0.133. Крутой рост FER BCH приходится на окрестность порога (FER ≈ 0.20 при p ≈ 0.108 и FER ≈ 0.50 при p ≈ 0.18) — «колено» брекетит p ≈ 0.133 (пунктирная линия).
- RS в BSC: порог по символам p_s = t/n = 2/15; в пересчёте на биты p = 1 − (1 − 2/15)^(1/4) ≈ 0.035. Кривая RS даёт FER ~0.4 уже при p ≈ 0.039 — согласуется (точечная линия).
- RS в символьном канале (раздел 2.4): «колено» при p_s ≈ t/n ≈ 0.133, эмпирическая кривая совпала с теоретической — прямое подтверждение порога.

## 5. Заключение

1. **Реализованы и провалидированы инструменты:** три модели каналов (BSC, SymbolError, Burst) собственной реализации, цикл Монте-Карло, метрики BER/FER/Throughput с 95% доверительными интервалами и двухвыборочным z-тестом. Корректность подтверждена 5 известными векторами (включая ручные примеры раздела 1 и побайтовое совпадение `galois` ↔ `reedsolo`) и совпадением кривой Монте-Карло с точной теоретической FER.

2. **Направление А.** Две реализации одного кода RS(255,223) дают **идентичные** FER/BER (z = 0, p-value = 1.0) — гипотеза А1 подтверждена. По скорости `reedsolo` оказался в ≈ 52 раза **быстрее** `galois` при поблочном декодировании длинного кода — гипотеза А2 (об ускорении `galois` в 3–5 раз) **опровергнута**; причина — накладные расходы `galois` на вызов при гранулярности «один блок», где векторизация numpy не работает.

3. **Направление Б.** Помехоустойчивость при равной символьной избыточности определяется структурой ошибок канала: в BSC лучше **BCH(15,7)** (на 1–2 порядка по FER, за счёт вдвое большей битовой избыточности и меньшей экспозиции), в пакетном канале лучше **RS(15,11)** (FER в ≈ 3–4 раза ниже, пакет ≤ 8 бит укладывается в 2 символа). Гипотеза Б1 подтверждена, гипотеза Б3 подтверждена в части пакетного канала и уточнена в части BSC. Положение «колена» кривых согласуется с теоретическим порогом p ≈ t/n.

**Главный практический вывод:** выбор между РС и BCH при фиксированной избыточности диктуется не «силой» кода вообще, а соответствием единицы исправления (символ vs бит) статистике ошибок канала; выбор библиотеки — компромисс между удобством/скоростью (`reedsolo` для RS над GF(2⁸)) и общностью (`galois` для произвольных полей и BCH).
